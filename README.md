# Voxel Converter for Unreal Engine

A Blueprint-based scene voxelization tool built with an Unreal Engine **Editor Utility Widget**. It samples scene collision within a defined region, quantizes hit positions into voxel coordinates, and organizes the results into chunks for preview and management.

The tool provides an editor workflow for experimenting with collision-based surface voxelization and chunk-based scene organization.

> Built for **Unreal Engine 5.4**. The core tool is implemented in Blueprints and does not require C++ compilation.
>
> **Current limitation:** Only `Voxel Size = 100.0` and `Group Size = 4.0` are supported. Entering other values in these controls currently causes bugs. Parameter generalization is still in development.

## Features

- Sample scene collision within a specified 3D scan region.
- Identify surface positions through ray traces.
- Convert sampled world positions into discrete voxel coordinates and data.
- Group generated results into chunks for managing larger regions.
- Inspect sampled positions before conversion using debug spheres.
- Scan, visualize, convert, and clear results through an Editor Utility Widget.
- Explore the workflow using the included example level and Chunk / Preview Blueprints.

## Requirements

- **Unreal Engine 5.4**
- **Windows** — the project defaults to DirectX 12 / Shader Model 6.
- **Modeling Tools Editor Mode** plugin enabled, as declared in the `.uproject` file.

## Quick Start

1. Clone or download this repository.
2. Open `MaptoVoxelEditorTool/MaptoVoxelEditorTool.uproject` with Unreal Engine 5.4.
3. If prompted, enable **Modeling Tools Editor Mode** and restart the editor.
4. Locate the following asset in the Content Browser:

   ```text
   Content/EditorUtilites/EUW_VoxelConverter
   ```

5. Right-click the asset and select **Run Editor Utility Widget**.
6. Configure the scan region. Keep **Voxel Size** at `100.0` and **Group Size** at `4.0`.
7. Run **Scan**, inspect the results with **Visualize**, then click **Convert**.
8. Use **Clear** to remove the current generated results before generating another batch.

## How It Works

The tool separates scene sampling from result generation:

```text
Scan Region + Parameters
          |
          v
Scene Collision Sampling
          |
          v
Raycast Hit Positions in World Space
          |
          v
Discrete Voxel Coordinates and Data
          |
          v
Chunk Grouping
          |
          v
Generated Voxel Results
```

**Visualize** inspects the sampled positions before conversion. **Clear** removes the Actors generated by the tool for the current batch and resets the current generated results.

### 1. Define the Scan Region

The scan region limits the portion of the level to process. Restricting this region to the objects of interest reduces unnecessary sampling and makes the results easier to inspect.

### 2. Sample Scene Collision

The tool performs ray traces within the scan region and records valid hit positions. These positions describe surfaces encountered by the traces.

Sampling depends on collision geometry and collision responses. Objects without queryable collision will not produce valid samples. If a mesh uses simplified collision, the sampled shape may differ from its visible geometry.

This is a collision-based surface sampling workflow. A surface hit does not by itself establish that every voxel inside an object should be filled, and the tool should not be assumed to reconstruct a watertight solid volume.

### 3. Convert Positions to Voxel Coordinates

Voxelization maps continuous world positions onto a discrete 3D grid. The voxel size defines the world-space extent of each grid cell.

Conceptually, a common grid mapping is:

```text
GridCoordinate = floor((WorldPosition - GridOrigin) / VoxelSize)
```

The operation applies independently to the X, Y, and Z components. Positions within the same grid cell map to the same coordinate, allowing the scene samples to be represented in grid space.

> This formula explains the general principle. It is not a verified transcription of the Blueprint implementation; the actual origin, rounding convention, and duplicate handling depend on the graph.

Smaller cells can represent finer spatial detail, but only when the sampling pattern captures that detail. Decreasing cell size alone does not guarantee complete surface coverage.

### 4. Organize Results into Chunks

The conversion stage groups voxel data into chunks instead of treating the entire scan region as one undivided result. The project includes `BP_VoxelChunk` and Voxel / Chunk / Group data structures for this organization.

Chunk grouping provides a basis for spatial management. It does not, by itself, establish support for runtime streaming, level of detail, or a particular rendering optimization.

### 5. Preview and Generate

The preview stage displays debug spheres at sampled positions so that scan coverage and density can be checked before creating the final results. The conversion stage then creates the voxel chunks and associated data.

## Usage

### Prepare the Scene

Place the static objects you want to voxelize in the level and ensure that their collision can be queried by the tool's traces.

Included example assets:

```text
Content/Level/TestLevel1
Content/BluePrint/BP_VoxelChunk
Content/BluePrint/BP_VoxelPreview
```

Start with a small region containing a few simple objects. Inspect the sampled positions before processing a larger scene.

### Configure Parameters

| Parameter | Purpose | Current Support |
| --- | --- | --- |
| Scan Area | Defines the 3D region to sample. | Set this to the region of interest. |
| Voxel Size | Defines the world-space size of a voxel. | Use `100.0` only. Other values currently cause bugs. |
| Group Size | Parameter associated with voxel grouping. | Use `4.0` only. Other values currently cause bugs. |

The UI exposes numeric controls for voxel and group size, but arbitrary values are not yet supported. For smaller test runs, reduce the scan region while keeping these two values fixed.

### Scan and Visualize

- **Scan:** Sample the specified region and record valid voxel positions.
- **Visualize:** Display the current samples as debug spheres to inspect coverage and density.
- Run **Scan** again after changing the scan region or scene geometry. Changing settings does not update previously recorded samples automatically.

### Convert and Clear

- **Convert:** Generate voxel chunks and associated data from the scan results.
- **Clear:** Delete the Actors generated by the tool for the current batch and clear the current generated results.

Use **Clear** before repeating conversion to avoid leaving multiple batches in the level.

## Limitations and Troubleshooting

| Symptom | What to Check |
| --- | --- |
| No samples appear | Check the scan region, queryable collision, and the targets' responses to the trace channel. |
| The sampled shape differs from the visible mesh | Inspect the collision geometry used by the traces. |
| Parts of a surface are missing | Check scan coverage and whether the traces can reach those surfaces. |
| Generation behaves incorrectly after editing parameters | Restore `Voxel Size = 100.0` and `Group Size = 4.0`, clear generated results, and scan again. |
| Multiple batches remain in the level | Clear the current generated batch before converting again. |
| Large scans take too long | Reduce the scan region and validate the workflow on a smaller area first. |

Additional considerations:

- **Performance:** Larger scan regions increase processing work. In a generalized implementation, smaller voxel sizes can also substantially increase sampling and output costs. Arbitrary voxel sizes are not supported in this version.
- **Collision dependency:** Results reflect the collision queried by the tool. Rendered appearance alone is not sufficient for sampling.
- **Surface coverage:** Collision sampling does not guarantee complete coverage of hidden surfaces or interior volume filling.
- **Preview overhead:** Dense debug-sphere previews can add editor overhead; evaluate conversion performance separately from preview display.
- **Version compatibility:** The project targets UE 5.4. Other versions may prompt you to upgrade project files or assets.
- **Scope:** This version documents spatial voxelization. Material/color capture, runtime streaming, and LOD are not documented as supported features.
